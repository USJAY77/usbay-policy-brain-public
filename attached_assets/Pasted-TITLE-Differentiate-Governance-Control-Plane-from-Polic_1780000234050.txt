TITLE: Differentiate Governance Control Plane from Policy Enforcement Gateway while keeping shared truth sync

AGENT: Replit Agent only

OBJECTIVE:
The Governance Control Plane and Policy Enforcement Gateway must stay synchronized, but they must NOT look like the same product screen.

Both surfaces now share too much visual structure. This creates role confusion for enterprise users.

DO NOT TOUCH:
- shared truth payload
- policy hash sync
- audit hash sync
- fail-closed semantics
- replay protection
- validators
- evidence verification
- API contracts

- executive governance authority
- policy oversight
- risk posture
- business impact
- pilot recommendation
- regulator readiness
- report preview

Policy Enforcement Gateway must communicate:
- runtime enforcement
- API gateway control
- allow / deny / block decisions
- request lifecycle
- evidence capture
- audit health
- operational security

Governance Control Plane:

- executive summary first
- risk and business panels
- pilot and report CTAs

Policy Enforcement Gateway:
- operational gateway layout
- request pipeline first
- enforcement decision panel
- request log / audit event stream
- endpoint health and gateway controls

- policy hash
- audit hash
- runtime mode
- replay guard
- evidence health
- sync drift indicator

But the main body must be different.

Gateway headline:
“Policy Enforcement Gateway Active”

TASK 5 — NAVIGATION CLARITY

Tabs must clearly show:
- Governance Control Plane
- Policy Enforcement Gateway
- Audit Health

Active tab must visibly differ.

- all tests pass
