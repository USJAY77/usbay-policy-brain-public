5. FAIL-CLOSED VALIDATION
============================================================

Before ANY provider execution, validate:

- contract exists
- authorization exists
- authorization matches execution contract
- provider == allowed provider

- prompt/input hash matches authorized input

- output count is within limit
- duration is within limit
- budget/cost ceiling is not exceeded where enforceable
- timeout is valid
- execution has not already been consumed if single-use semantics apply
- publication remains false unless a separate human publication authorization exists

Missing or malformed required values MUST block.

No fallback-to-allow behavior.
