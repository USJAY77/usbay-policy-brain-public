3. READ-ONLY OUTER-CONTAINMENT CAPABILITY CHECK
Inspect only the capabilities needed for an independently managed Linux
boundary, such as an existing delegated cgroup v2 subtree or available
systemd user-service management.

Record concrete observations and uncertainty:
- Which manager or delegated boundary is accessible.
- Whether it is independent of the harness controller.
- Available whole-boundary termination and empty-state observation.
- How a controller starts inside the boundary before it can spawn children.
- Whether tasks could move outside the boundary.
- Which component owns deadlines, cleanup and direct-child reaping.

Do not create units/cgroups, change permissions, use sudo, install packages,
write cgroup controls or start probe workloads.

A visible cgroup mount or executable is not proof of usable delegation.
Read-only inspection cannot prove native kill/empty semantics.

4. IMPLEMENTATION DECISION
Reuse an established available mechanism; do not build a custom process
supervisor merely to avoid reporting an environment limitation.

If a plausible supported backend is identified:
- Implement one narrow adapter and injectable orchestration for future use.
- Limit it to the named validation entrypoints; do not expose a generic
  arbitrary-command runner.
- Keep production native invocation disabled in this increment.
- Establish the boundary before releasing any controller workload.
- Keep cleanup authority outside the controller boundary.
- Identify the exact task-owned boundary; never signal ambient groups.
- Use distinct execution and cleanup budgets.
- Require explicit boundary-empty evidence and direct-child reaping.
- Persist failure evidence outside the kill boundary.
- Missing authority, identity mismatch, backend errors, absent empty-state
  proof or deadline exhaustion must never produce PROVEN.
- Document what happens if the outer manager itself fails.
- State that process containment is not a complete security sandbox.

If no usable backend can be established:
- Complete the evidence-directory change and its tests.
- Report outer containment BLOCKED with the exact missing capability.
- Provide the minimum external environment requirement.
- Do not add a fake-success backend, silently fall back to killpg/timeout,
  broaden permissions or mark native execution ready.

- Cleanup failure or non-empty boundary fails closed.
- Missing/malformed evidence fails closed.
- Successful cleanup requires boundary-empty proof and direct-child reaping.
- Evidence remains available after simulated controller failure.
- Unavailable backend prevents launch.
